设计范围与实现方案

默认方案：文档和代码在右侧终端 pane 预览，完整 HTML/PDF 在当前查看机器的浏览器中打开。模型设置继续在 Herdr 侧操作。插件独立于 Herdeo/Paseo，Claude Code、Codex 及其他终端程序共享同一套文件打开逻辑。

已核实的 Herdr 约束

  • 0.9.3 的 manifest 支持 link_handlers，通过 Ctrl+点击将已识别的链接交给插件；Mac 也是 Control。
  • 插件面板是终端程序，不是内嵌 WebView。完整交互 HTML 不能靠一个终端插件面板直接实现。
  • 0.9.3 与 0.9.5 的普通文本自动检测主要接受 HTTP/HTTPS。显式 OSC 8 文件链接可进入链接分发，但普通路径、相对路径及文字形式的 file:// 不自动获得通用点击支持。
  • 要满足原回答里任意文件路径都可点击，设计需要一处 Herdr 路径检测扩展。仅“选中文本后按快捷键”可作为后备操作，不算完成原需求。

实现拆分

来源 pane 的路径点击
　→ Herdr 路径识别扩展 / 已有显式终端链接
　→ Lens 文件引用（机器、会话、pane、项目目录、路径、行列）
　→ 来源机器上的只读文件解析与读取
　→ 右侧终端渲染器
　→ 完整预览：本地伴随程序 → SSH 文件读取 → 本机浏览器
  • Herdr 小扩展：仅扩展路径点击入口与可配置的本地文件 opener。传递来源 endpoint/pane 和内容 revision；复用现有插件动作，不重写 agent 文本。
  • 主机插件：解析绝对路径、~/、相对路径、Markdown/OSC 8 文件链接及行列后缀。依据来源 pane 的目录解析，检查目标存在，再提供只读文件或目录内容。
  • 预览器：每个来源 workspace 复用一个预览 pane，不不断分屏；支持源码/预览、搜索、返回与文件变更提示。关闭预览只关闭 viewer。
  • 完整浏览器预览：查看机器运行本地伴随程序，使用已有 SSH 身份连接远端 reader；接收经过机器绑定的文件引用，在本机 loopback 视图渲染。远端插件执行 open/xdg-open 不能打开用户本机的浏览器，因此需要这一客户端入口。
  • 文件身份：缓存按机器＋会话＋规范化真实路径区分。相同路径在两台机器上不共用内容；历史相对路径无法唯一确定时显示候选或说明，不猜测。
  • 阅读行为：文件路径作为数据传递，不拼接成 shell 命令。HTML 在隔离视图渲染，只允许已绑定文件和获准的相对资源；不向网页暴露任意文件读取或执行接口。

实施顺序

  1. 用 Herdr 0.9.3 的显式链接验证插件打开右侧 pane；完成路径解析与 Markdown/代码/JSON 渲染。
  2. 补 Herdr 的裸路径点击与客户端 opener，验证 Unicode、空格、软换行、行列和历史输出的点击位置。
  3. 接入本地伴随程序与 SSH reader，完成 HTML/PDF/图片完整预览。
  4. 在本机与两台远端机器验证同名路径、断线、文件更新及多 workspace 复用；优先将 Herdr 小扩展提交上游，避免长期维护整套 fork。

验收标准

  • 分别从 Claude Code、Codex 原生回答点击路径，都能打开同一份真实文件；路径是纯文本时也可用。
  • 代码路径含行列时，预览定位到相应行；空格、中文、括号和文件名里的 # 不被误拆。
  • 两台机器返回同一个路径时，读到各自机器的文件；来源机器始终可见。
  • 切换机器/工作区时，旧读取结果不覆盖新预览；断线与文件不存在有明确提示。
  • 预览过程中，agent PID、原生 session ID、输入草稿和正在执行的任务保持；文件更新只刷新 viewer。
  • 浏览器预览加载正确的相对 CSS/图片；不需要把服务暴露到公网。
